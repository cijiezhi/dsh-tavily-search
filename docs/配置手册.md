# 配置手册

> 面板功能的说明见 [使用手册](./使用手册.md)。

配置有**两个来源**，运行时的生效值是两者合并：

```
schema 默认值  →  profile 的 Config（cordis.yml / cordis.patch.yml）  →  state.json 的用户覆盖
```

面板改的开关与精度写进 `state.json`（用户级覆盖，优先级最高）；
面板没动过的字段始终由 Config 决定。

## Config 项

写进 profile 的 `cordis.yml`，或在 `cordis.patch.yml` 里覆盖本插件的行：

```yaml
- id: dsh-tavily-search
  config:
    searchDepth: advanced
    maxResults: 20
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `providerId` | `tavily` | 注册 id，必须与 `web` 行的 `searchProvider` 一致 |
| `apiKeyEnv` | `TAVILY_API_KEY` | 凭证引用名（POSIX 环境变量名形式） |
| `maxResults` | `20` | 结果条数上限（1–20） |
| `searchDepth` | `advanced` | `basic` / `advanced` / `fast` / `ultra-fast`；advanced = 2 credits/次 |
| `topic` | `general` | `general` / `news` / `finance`；**只有 general 支持生成答案摘要** |
| `includeAnswer` | `advanced` | 模型 `web_search` 的摘要档位：`false` / `basic` / `advanced` |
| `directAnswerDetail` | `advanced` | 面板直搜的摘要档位 |
| `chunksPerSource` | `3` | 每条来源片段数（1–3，**仅 advanced 深度生效**） |
| `timeoutMs` | `30000` | 单次请求超时（1000–120000） |
| `includeUsage` | `true` | 让 Tavily 回传本次 credits（测试与直搜据此显示用量） |
| `endpoint` | `''` | 留空 = 官方端点；可指向自建代理或本地 mock |
| `fallbackModel` | `''` | 兜底搜索的模型名；留空用 `deepseek-v4-flash` |
| `fallbackBaseUrl` | `''` | 兜底搜索的基址；留空用 `https://api.deepseek.com/anthropic/v1` |
| `allowLan` | `false` | 面板数据面是否接受非回环来源（**默认只允许本机**） |
| `fetch` | — | **测试钩子**（注入 fetch 实现），不属于用户可调项 |

> Config 的校验由插件自带的 Standard Schema 完成（`~standard.validate`），
> 非法枚举与越界数字会在加载时报错，不会静默取默认值。

## 状态文件（面板改动的那一份）

| 项 | 值 |
|---|---|
| 路径 | `$DSH_HOME/dsh-tavily-search/state.json`（DSH_HOME 未设时回退 `~/.dsh`） |
| 字段 | `enabled` / `searchDepth` / `includeAnswer` / `directAnswerDetail` / `maxResults` / `apiKeyEnv` |
| 写入 | 面板改动，或 `POST /api/dsh-tavily/state` |
| 覆盖规则 | 字段为 `undefined` 时不参与覆盖，回落 Config |
| 落盘方式 | 原子写（先写临时文件再 rename），损坏文件按空状态处理（面板不会因此打不开） |

**这里永远不放 Key** —— Key 只进官方凭证库。宿主的写入接口有白名单校验，
提交 `apiKey` 之类的字段不会落盘（测试里有断言）。

## 面板数据面（HTTP 路由）

挂在 `ctx.webServer` 上，全部是 `exact` 具名路由，前缀 `/api/dsh-tavily`：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/state` | GET | 返回状态 + 生效配置 + 凭证引用名 |
| `/state` | POST | 写状态（白名单字段，越界数字会夹到合法区间） |
| `/credential` | GET | 凭证概况（`configured` / `source` / `writable` / `usable`），**不含明文** |
| `/credential` | POST | `{apiKey}` 保存，或 `{action:'clear'}` 清除 |
| `/search` | POST | 面板直搜（答案 + 来源链接，无正文片段） |
| `/test` | POST | 连通性测试（真打一次 Tavily） |
| `/quota` | POST | 查额度（Tavily `GET /usage`） |

### 认证与安全

- 默认**只接受回环来源**（`Host` 必须是 `localhost` / `127.0.0.1` / `::1`），否则 403；
- 带 `Origin` 头时其 hostname 也必须是回环（防 DNS rebinding / CSRF）；
- 请求体上限 64 KB；响应 `cache-control: no-store`；
- `allowLan: true` 会放行非回环来源 —— **这个服务不带 TLS、不带认证，等于把读写 Key 的口子
  开给同网段**，只在你清楚后果时开。

## 安装形态（bundle patch）

插件自带的 `cordis.patch.yml` 做三件事：

1. `insert` 自己的行；
2. 顶层按 id **停用**内置搜索行 `web-search-deepseek`；
3. 顶层按 id 把 `web` 行的 `searchProvider` **钉死**为 `tavily`（并重述 `fetchProvider`）。

> 为什么「停用 / 覆盖」必须是顶层按 id 的块，不能放进 `insert`：
> 放进 insert 会被当成「新建同 id 条目」，与官方 base 里已插入的同 id 条目冲突 →
> `duplicate loader entry id` → 整棵 plugin tree 加载失败（boot 崩）。这是本插件 v1 的崩溃根因。
>
> 为什么必须钉死 `searchProvider`：seam 在「未配置 id 且有多个可用 provider」时抛
> `WEB_PROVIDER_AMBIGUOUS`；在「配置了 id 但不可用」时报错而不回落。钉死一个 id 是唯一
> 不触发歧义的组合。

### 恢复内置搜索

把 bundle patch 里的 `disabled: true` 改成 `false`，并删掉 `web` 行的 `searchProvider`，
然后重启 DSH。
